# DOM-MTG — API contracts

API contracts owned by [DOM-MTG](README.md) ([STD-003 R2](../../governance/standards/STD-003-REPOSITORY-DOCUMENT-STRUCTURE.md)). Transport, authorization and the error envelope are [API-001](../platform/contracts.md#api-001--http-api-transport-authorization-and-error-envelope). All are `proposed` and written on 2026-10-01 from the code of release 0.5.1 and from [SDD-004](../../features/FEAT-004-meeting-task-manager/design.md) section 3; API-021 and API-022 are interfaces of FUNG Desktop, an external system that the user's browser calls directly.

### API-019 — Meeting commit
Relations: relates_to: FR-012-007, FR-012-008, FR-012-009, FR-011-009, FR-011-010, FR-010-009, SDD-004, API-001, API-008; decided_by: ADR-002, ADR-004
Owner: DOM-MTG

**Status:** proposed. **Served by:** SRV-001, SRV-002. **Code:** `apps/api/meeting-commit.mjs` (`commitMeeting`), routed in `apps/api/api.mjs`; the write path is `apps/api/workspace.mjs:writeDomain`, the pure rules `apps/web/src/content/meeting/model.mjs` (`commitBatch`, `canonicalChoices`, `isBatchStale`).

| Operation | Auth | Request | Success | Errors |
|---|---|---|---|---|
| `POST /businesses/{b}/meeting-commits` | Member, operator, and the meeting and batch must be readable by the viewer | `{meetingId, batchId, reviewRevisionId, reviewHash, sourceHash, choices}`; `choices` is an array of objects, one per proposal, each with `proposalId`, `mode` (`create`, `link`, `update` or `skip`) and, as the mode needs, `title`, `description`, `responsibleId` (R, required to create or update), `accountableId`, `dueDate`, `taskId` and `taskVersion` (to link or update), `week`, `priority`, `priorityNote` (FR-012-007) | 200 `{receipt, replayed, workspace}`: the receipt `{id, batchId, idempotencyKey, payloadHash, payload, origin:"server", taskIds, mappings:[{proposalId, taskId}], committedAt}` as the viewer may see it (task IDs and mappings of tasks the viewer cannot read are left out), whether this was a replay, and the viewer's workspace as `GET /workspace` returns it (API-008) | listed below |

- **The request supplies no key, task ID, audience, receipt or hash.** The server derives the idempotency key `sourceInstanceId:projectId:recordingId:reviewId:reviewHash:batchId`, the task IDs (task codes `TSK-nnnn`), the audience (from the stored meeting, FR-011-009) and the payload hash (of the canonical form of `choices`: choices ordered by `proposalId`, keys sorted).
- **Errors.** 401 `AUTH_REQUIRED` for a Guest; 422 `ข้อมูลการสร้างงานจากประชุมไม่ถูกต้อง` for a body that is not an object with string `meetingId` and `batchId` and an array of object `choices`; 404 `ไม่พบประชุม` or `ไม่พบร่างงาน` for a meeting or batch that does not exist or that the viewer cannot read (one answer for both); 404 `ไม่พบงาน` for a task to link or update that is missing or unreadable; 409 `COMMIT_CONFLICT` `ร่างนี้เคยบันทึกแล้วด้วยรายละเอียดต่างกัน` (the batch was committed with other choices); 409 `STALE_BATCH` `ร่างเก่าใช้สร้างงานไม่ได้ กรุณาตรวจฉบับใหม่` (`reviewRevisionId`, `reviewHash` or `sourceHash` differ from the stored batch, or the meeting has a newer review or source); 409 `VERSION_CONFLICT` (a `taskVersion` differs); 422 `AUDIENCE_WIDER` (updating a task that is visible to more people than a restricted meeting's participants); 422 with code null for the pure rules of the commit (for example `เลือกรายชื่อ R ก่อนสร้างงานจากประชุม`, evidence that does not match the reviewed revision, no choice selected, a restricted meeting with no participant); 422 `MEMBER_INACTIVE` for an Inactive R or A; the visibility rules of FR-011-011 (`WIDEN_DENIED` 403; `REASON_REQUIRED`, `TEAM_REQUIRED`, `NAMED_REQUIRED`, `SELF_EXCLUDED`, `LEVEL_INVALID` 422), which this route answers with the status and the Thai message of `CHANGE_ERRORS` and code null, because the commit writes through the in-process path of API-008 and only API-016 and API-017 attach the code string; 409 (`40001`) when three attempts all lose a serialization race.
- **One transaction.** The Business row is locked, the tasks (with RACI, viewers, week entries and history events), the receipt, the batch's `commit_key` and `commit_payload_hash`, the `meeting_task_links` rows with their evidence quotes, one `commit` change event (EVT-001) and `domain_revision` are written together, or none (FR-012-009). The commit goes through the in-process write path of API-008, which applies the task rules and counts as the task domain's contract (PLAN-002 D1).
- **Audience.** Tasks created from a `restricted` meeting are `restricted` with the meeting's participants as viewers, fixed at commit; tasks of any other meeting get no audience of their own and keep the default `business` (FR-011-009). A meeting whose transcript is held on the recording machine commits on its spans, without quotes (FR-011-010).
- **Idempotency.** The same choices again (in any order) answer 200 with `replayed:true`, the same receipt and tasks, and write nothing. Two identical requests at once make one set of tasks: the second fails to serialize, is retried up to two more times (`api.mjs`) and replays. A receipt made by the browser before this operation existed (no `origin`) replays by its plain payload.
- **Not through this route.** A whole-workspace save that carries a receipt the server did not store answers 422 `RECEIPT_SERVER_OWNED` (API-008).
- **Specified by.** [FR-012-007](../../features/FEAT-012-meeting-intake/requirements/FR-012-007-assignment-check.md), [FR-012-008](../../features/FEAT-012-meeting-intake/requirements/FR-012-008-idempotent-commit.md), [FR-012-009](../../features/FEAT-012-meeting-intake/requirements/FR-012-009-commit-one-transaction.md), [FR-011-009](../../features/FEAT-011-visibility-and-confidential-meetings/requirements/FR-011-009-confidential-meeting-tasks.md); design in the [SDD-004 amendment](../../features/FEAT-004-meeting-task-manager/design.md#proposed-amendment--server-side-meeting-commit-plan-002-wi-09).

### API-020 — Transcript upload (confidential meetings)
Relations: relates_to: FR-011-010, FR-011-006, SDD-004, SDD-011, API-001, API-008; decided_by: ADR-004
Owner: DOM-MTG

**Status:** proposed. **Served by:** SRV-001 in practice (the route exists on SRV-002 but the operator is not a Member and is refused). **Code:** `apps/api/workspace.mjs` (`uploadTranscript`), routed in `apps/api/api.mjs`.

| Operation | Auth | Request | Success | Errors |
|---|---|---|---|---|
| `POST /businesses/{b}/meetings/{id}/transcript` | a Member who is a participant of the meeting | `{reason, sources, reviews, batches}`: `reason` is a non-empty text; the three arrays hold the full source revisions, review revisions and draft batches of which the server stores only the text-free stubs | 200 the viewer's workspace as `GET /workspace` returns it (API-008) | 404 `ไม่พบประชุม` (missing or unreadable, `id` being the meeting's UUID or its workspace ID); 403 `เฉพาะผู้เข้าร่วมประชุมอัปโหลด transcript ได้` (the operator, who is not a Member, or a Member who is not a participant); 422 `ระบุเหตุผลที่อัปโหลด transcript`; 409 `transcript ของประชุมนี้อยู่บน cloud แล้ว`; 422 `transcript ที่ส่งมาไม่ตรงกับฉบับที่บันทึกไว้` |

- **What is accepted.** Only the full content of the stubs already stored: each document sent must be a whole revision (not itself withheld, with well-formed segments), and when its text is removed it must equal the stored stub; a review's hash is recomputed from its segments; every batch must equal its stub and its evidence quotes must be found in its review. Anything else is the 422 above and nothing changes.
- **Effect.** The segments and quotes are stored, the meeting's `transcript_custody` becomes `cloud`, a change event (`meetings`, `transcript_upload`, with the reason and the revision and batch IDs) is written and `domain_revision` rises, in one transaction. The upload is an explicit, audited choice of a participant (SEC-019).
- **Idempotency.** A second upload for the same meeting is 409 (the custody is no longer `local_only`).
- **Specified by.** [FR-011-010](../../features/FEAT-011-visibility-and-confidential-meetings/requirements/FR-011-010-transcript-custody.md), [FR-011-006](../../features/FEAT-011-visibility-and-confidential-meetings/requirements/FR-011-006-meeting-visibility.md).

### API-021 — FUNG Desktop local API (as consumed by the web client)
Relations: relates_to: FR-012-001, FR-012-002, FR-012-003, NFR-012-001, SDD-004
Owner: DOM-MTG

**Status:** proposed. **Provider:** FUNG Desktop on the user's machine (a separate repository; the routes were read at FUNG commit `de696eaa68dbf9705bf57b765ad00b73f33ca282` on 2026-09-30 in [SDD-004 §2](../../features/FEAT-004-meeting-task-manager/design.md) and were not re-inspected for this contract). **Consumer:** the web client `apps/web/src/content/meeting/fung-client.mjs` (`createFungClient`), from the user's browser straight to FUNG; the Zuri-Go server never calls FUNG and never proxies it.

**Connection.** The user pastes the Connect URL of FUNG › Settings › Runtime. The client accepts only `http` or `https` at `127.0.0.1`, `localhost` or `[::1]`, with no user name, password or query, a path of `/` or empty, and a token of 1 to 512 characters without whitespace in the fragment; anything else is refused before a request is sent (`เชื่อมต่อได้เฉพาะ FUNG บนเครื่องนี้`, `Connect URL ต้องมี token ของรอบที่เปิด FUNG`). Every request goes to that origin with `Authorization: Bearer {token}` (the token is never in a URL), `redirect: error`, `credentials: omit` and `cache: no-store`, with a time limit of 180 seconds (300 for an upload). The token lives in the page's memory only and is cleared on disconnect (FR-012-001, SEC-015).

| Operation | Request | Success (as the client requires it) | Errors as the client reports them |
|---|---|---|---|
| `GET /recordings` | none | 200 `{recordings:[…]}`; each has at least `id` and `projectId`, and may show `projectName`, `status`, `durationMs`. The first successful call is what makes FUNG “connected” | |
| `POST /recordings/import` | the file as the body; `Content-Type` the file's type or `application/octet-stream`; `X-Fung-Filename` the printable-ASCII name, or `meeting-upload.{extension}` | 200 `{jobId, recordingId, projectId}`, all three present | |
| `GET /jobs/{jobId}` | none | 200 `{job}` | `ไม่พบสถานะ job` when `job` is absent |
| `GET /recordings/{id}/transcript` | none | 200 `{transcript:{segments:[{id, startMs, endMs, text, speakerName}]}}`: the legacy form, used only when API-022 is absent and the user has confirmed the FUNG instance; the client makes it a snapshot with `sourceMode` `legacy`, no native revision, `reviewState` `unknown` and unknown coverage | `ไม่พบ transcript` |
| `GET /recordings/{id}/audio[?channel=]` | none | the audio bytes, played through a blob URL | |

- A non-2xx answer is shown as `Token หมดอายุหรือไม่ถูกต้อง กรุณาคัดลอก Connect URL ใหม่` for 401 and `FUNG ตอบ HTTP {status}` otherwise, followed by ` · ` and the `error` text (at most 160 characters) when the body is JSON with an `error`; a request that gets no answer is `ติดต่อ FUNG ไม่ได้ …`.
- The client accepts a file only when it is larger than 0 bytes and at most 512 MiB and its extension is `wav`, `mp3`, `m4a`, `mp4`, `webm`, `ogg`, `flac`, `aac`, `mpeg` or `mov`.
- `GET /health` is listed in SDD-004 §3.1 as a way to recognise FUNG; the client does not call it.
- **Idempotency.** The reads are safe to repeat. The client sends one import per user action; how FUNG treats a repeated import is not specified here.
- **Specified by.** [FR-012-001](../../features/FEAT-012-meeting-intake/requirements/FR-012-001-fung-local-connection.md), [FR-012-002](../../features/FEAT-012-meeting-intake/requirements/FR-012-002-audio-intake.md), [FR-012-003](../../features/FEAT-012-meeting-intake/requirements/FR-012-003-transcript-provenance.md), [SDD-004 §3.1](../../features/FEAT-004-meeting-task-manager/design.md). Not run: a connection to an installed FUNG Desktop (FR-012-001 notes).

### API-022 — FUNG meeting-task-manager integration, protocol version 1
Relations: relates_to: FR-012-001, FR-012-003, FR-012-004, FR-012-005, FR-012-006, NFR-012-001, SDD-004, API-021
Owner: DOM-MTG

**Status:** proposed. **Provider:** an adapter in FUNG Desktop that does not exist yet in the installed app (SDD-004 §3.2: “ยังไม่มี implementation”). **Consumer:** `apps/web/src/content/meeting/fung-client.mjs` (`connect`, `snapshot`, `draft`) and `Meetings.jsx`, which already speak it. The routes live under `/integrations/meeting-task-manager/v1` of the FUNG origin and use the connection, token and origin rules of API-021. This contract is the one SDD-004 §3.2 to §3.4 proposes, with the fields the client sends and requires; the provider's behavior is not verified.

| Operation | Request | Success | Errors |
|---|---|---|---|
| `GET /integrations/meeting-task-manager/v1/capabilities` | none | 200 `{protocolVersion, snapshot:{available}, actionDraft:{available, reasonCode?}}` and a readiness reason, without secrets | 404 means the connection stays in legacy mode (API-021 transcript route, no drafts); a `protocolVersion` other than 1 is refused (`Protocol ตัวเชื่อม FUNG ยังไม่รองรับ`) |
| `GET /integrations/meeting-task-manager/v1/recordings/{recordingId}/snapshot` | none; the client calls it only when `snapshot.available` is true | 200 the source snapshot below | |
| `POST /integrations/meeting-task-manager/v1/action-drafts` | the draft request below, JSON | 200 the draft response below | |

- **Source snapshot.** `schemaVersion`, `sourceInstanceId`, `projectId`, `recordingId`, `sourceMode`, `sourceRevision` (nullable), `sourceCursor` (nullable), `contentHash`, `capturedAt`, `meetingStartedAt` (nullable), `timezone`, `segments[]`, `coverage`. A segment has `segmentId`, `nativeRevisionId` (nullable), `startMs`, `endMs` (integer milliseconds), `text`, `speakerLabel` (nullable), `reviewState` (`unknown`, `committed` or `reviewed`) and `sourceRef`. `sourceInstanceId` identifies the local connection and is not the token. `contentHash` is the hash of the canonical UTF-8 JSON of project and recording, source mode and revision, the ordered segment IDs, times, text and speaker, and the coverage, without `capturedAt`. A legacy source has no native revision (null, never a made-up 1). An error, a gap in the source and empty speech are three different states, and unknown coverage is shown as unknown.
- **Draft request.** `requestId`, `sourceInstanceId`, `projectId`, `recordingId`, `expectedSourceHash`, `reviewRevisionId`, `reviewHash`, `reviewedSegments[]` (`segmentId`, `startMs`, `endMs`, `text`, `speakerLabel`), `locale` (the client sends `th-TH`), `meetingStartedAt`, `timezone` (`Asia/Bangkok`). The client keeps one `requestId` per reviewed revision and makes a new one for another.
- **Draft response.** `draftBatchId`, `requestId`, `sourceHash`, `reviewRevisionId`, `reviewHash`, `modelRunRef`, `modelName`, `generatedAt`, `items[]`; at most 30 items, each with `proposalId` (unique in the batch), `kind` (`task`, `decision` or `question`), `title`, `deliverable`, `suggestedResponsibleLabel`, `suggestedDueText`, `suggestedDueDate` (the last three nullable), `evidence[]` and `unresolvedFields[]`. An evidence entry is `segmentId`, `startMs`, `endMs`, `quote` and `reviewRevisionId`; the consumer accepts it only when the quote is text of that revision's segment and the times lie inside it, and the batch only when its `reviewRevisionId`, `reviewHash` and `sourceHash` match the stored ones.
- **Rules of the provider.** `draftBatchId` is derived deterministically from `requestId` and the source and review identity, so a retry gives the same batch; the model proposes text and has no tool, no choice of destination and no power to create a task; no credential, email or list of other people goes into the prompt; transcript content is untrusted data (NFR-012-001); only a local provider that FUNG reports ready is used, with no fallback to a cloud model; the routes open no external meeting dispatch and no MCP write tool.
- **Idempotency.** The draft request is idempotent by `requestId`; a new extraction needs a new `requestId` and goes through duplicate review before a commit (API-019).
- **Specified by.** [SDD-004 §3.2 to §3.4](../../features/FEAT-004-meeting-task-manager/design.md), [FR-012-003](../../features/FEAT-012-meeting-intake/requirements/FR-012-003-transcript-provenance.md), [FR-012-004](../../features/FEAT-012-meeting-intake/requirements/FR-012-004-review-revision.md), [FR-012-005](../../features/FEAT-012-meeting-intake/requirements/FR-012-005-action-extraction.md), [FR-012-006](../../features/FEAT-012-meeting-intake/requirements/FR-012-006-evidence.md). Not run: inference with a real configured model (FR-012-005 notes).
