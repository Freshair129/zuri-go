# A restricted meeting with an Inactive participant cannot create tasks — WI-12 design gap D2 (found 2026-10-01, local build)
Symptom: committing a draft batch of a restricted meeting answers 422 "สมาชิกนี้ปิดใช้งานอยู่ กรุณาเลือกคนที่ Active" whenever one participant is an Inactive Member, although the chosen R and A are Active. No task is created.
Evidence: reproduced on the local database (schema 7, isolated QA Business): four seeded Members, the third set Inactive, a restricted meeting with participants m0, m1 and the Inactive m2, `commitMeeting` by m0 with R = m3 and A = m0 gave status 422 and that message; after m2 was made Active again the same request committed. The message comes from `person()` in `apps/web/src/content/meeting/model.mjs`: `saveTask` ran every `viewerIds` entry through `person()`, which refuses an Inactive Member unless it is the `old` value, and `commitBatch` hands the meeting's participants to `saveTask` as `viewerIds` (FR-011-009).
Root cause: `person()` encodes "an Inactive Member takes no new assignments" (an R, A, C or I, which is work), but it was reused for named viewers, which are access. A participant or viewer who is Inactive is only someone who may still read; refusing them also cuts the audience the restricted meeting must give its tasks. The server had no rule of its own: only the client model enforced Inactive at all, so the task API and the whole-workspace save accepted an Inactive R (the other half of the same gap).
Why escaped: tests of the inactive rule covered R only (`duplicate names remain separate; inactive cannot take new assignments`), and the commit tests used Active participants, so the two rules never met. The server-side rule was assumed to follow from the client model.
Prevention: owner decision D2 of 2026-10-01 separates the two: the model checks existence only for viewers; the server (task API `createTask`/`updateTask` and `writeDomain`, hence the meeting commit) refuses an Inactive Member in a new R, A, C or I with 422 and the model's own message, and keeps a role the task already had with that Member. Tests cover an Inactive viewer and participant (allowed, audience intact), an Inactive new R (refused), an Inactive existing R (kept), on the model, the task API and the commit. A backup import (operator restore) is not subject to the rule.
