# Meeting evidence quotes readable outside the meeting's audience — FEAT-011 P1 (local build, not released)
Symptom: a person who may read a task but not the meeting it came from could still read that meeting's evidence quotes, through two read paths: the task's history events in `/workspace`, and the task row's `legacy_metadata.sourceRefs` in `/state`.
Evidence: P1 `readLegacy` removed `sourceRefs` for hidden meetings from the task object, but returned `legacy_task_event` rows whose `after_data` holds the full task snapshot, quotes included (found by the P3 track while writing the AC-011-009 test, 2026-10-01). `snapshot()` (`apps/api/service.mjs`) returns `tasks` rows with their `legacy_metadata` unfiltered, and `writeDomain` stores `sourceRefs` (with `evidence[].quote`) in `tasks.legacy_metadata` (noted by the WI-09 design track). Row-level security cannot help: the rows are the visible task's own rows; the quotes are nested JSON.
Root cause: the P1 filter treated "content follows its item" (FR-011-008) per row, but meeting quotes are copied into task-level JSON (task metadata and history snapshots), whose audience is the task, not the meeting.
Why escaped: P1 tests checked which rows each viewer gets, not the nested JSON of visible rows; the withheld-reference test read only `readLegacy`'s task object.
Prevention: withhold quotes of unreadable meetings in every read path that returns task JSON (`readLegacy` tasks and events, `snapshot` task metadata) and test both paths for a reader of the task who is not a participant of the meeting. Longer term, PLAN-002 WI-09 keeps quotes only in `meeting_task_links` (SDD-004 proposed amendment). Neither path reached production: P1 is local only and production has no meetings.
