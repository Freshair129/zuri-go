# Task history events store meeting evidence quotes in change_events — WI-12 design gap D14 (found 2026-10-01, local build)
Symptom: after a server meeting commit, a direct query of `change_events` (entity_type `legacy_task_event`) finds the verbatim quote of the meeting evidence, although WI-09 keeps quotes only in `meeting_task_links` and strips them from the task row.
Evidence: reproduced on the local database (schema 7, isolated QA Business): a restricted meeting with one proposal whose evidence quote was a marker string, committed by a participant; of 12 `legacy_task_event` rows one, the `task-created` event of the new task, contained the marker (its `after_data.detail.after.sourceRefs[].evidence[].quote`). `writeDomain` (`apps/api/workspace.mjs`) applies `bare()` to the task row's `sourceRefs` (line of `metadata=withoutAccess(...)`) but inserts `change_events.after_data` from the client's event as it came. The client's events are task snapshots (`event(s,'task-created',t.id,{before,after})`) and, for `source-linked`, the reference itself; `readLegacy` re-attaches quotes to `sourceRefs`, so every later `task-updated` snapshot carries them too.
Root cause: WI-09 moved the quote out of the task row but only for the row; the history events are a second copy of the same task JSON and were not given the same rule. `withholdQuotes` hides them on read for a viewer outside the meeting, but the stored rows, backups and any direct query still hold the text.
Why escaped: the WI-09 tests asserted "no quote in the task row or the links for someone outside the meeting" and read events only through `readLegacy`, which filters them; nothing queried `change_events` itself.
Prevention: owner decision D14 of 2026-10-01: `writeDomain` applies the `bare()` rule to the snapshots in an event (`detail.before`, `detail.after`, and a `source-linked` detail that is a reference) before storing it, so a reference whose evidence lives in `meeting_task_links` is stored without its quote; events written before the fix are left as they are (they stay withheld on read). Tests query `change_events` directly after a new commit and after a later task edit. Any new place that copies task JSON must go through the same rule.
