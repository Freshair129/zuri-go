# Guests read Member contact details (email, phone, notes) — WI-12 design gap D16 (found 2026-10-01)
Symptom: a Guest (no login) gets every Member's full name, nickname, team, position, email, phone and notes from the read paths, on the local server and, with the same code, on the hosted API in production (0.5.0).
Evidence: reproduced on the local database (schema 7, isolated QA Business): after setting an email, phone and note on a Member, a Guest `readLegacy` (`GET /workspace`) returned the member object with `email`, `phone`, `notes`, `fullName`, `nickname`, `team`, `position`, `seedMemberId`, and a Guest `snapshot` (`GET /state`) returned the `members` rows with the same values in columns and `legacy_metadata`. FEAT-011 narrowed what a Guest reads of tasks and meetings (FR-011-004…008) but the members table has only a Business-scope policy (`business_scope`), and `readLegacy` and `snapshot` copied all member columns for every viewer. The hosted code path is the same; the production database was not queried in this work.
Root cause: FEAT-011 defined audiences for work items only. Members were treated as a registry everybody in the Business may read, which was true while every reader was signed in; Guest mode (read-only, no login) is also a reader, and nothing limited member fields by viewer.
Why escaped: the visibility tests count tasks, meetings and quotes per viewer; none inspected the member fields a Guest receives. The interim Guest rule (ADR-004 D9) warns about HR or customer content in production but does not mention Member contact data.
Prevention: owner decision D16 of 2026-10-01: a Guest read returns only each Member's id, PID, display name and status on every path that lists members (`readLegacy`, `snapshot` and so `/state`; `/overview`, `/bootstrap` and the team routes do not list Members to a Guest); Members and the operator read everything as before. Tests check the keys a Guest receives on the local reads and on the hosted handler. The fix is a code change in the API; it takes effect in production only when a release is deployed, which this work does not do.
